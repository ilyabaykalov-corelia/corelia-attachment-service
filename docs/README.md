# Документация attachment-service

Сервис получает либо поток, либо metadata команды от доверенного internal
caller, резервирует/сохраняет blob и вызывает document/data контракты для
фиксации состава. Registry хранит состояния lifecycle; физическое удаление
выполняется только после перехода blob к удалению. Историческое вложение
остаётся доступным согласно версии документа, пока его ссылка не удалена
владельцем lifecycle.

Отсутствует общая транзакция между S3 и PostgreSQL: recovery/GC предназначены
для cleanup, а не для выдачи фиктивной атомарности. Список endpoint —
[API](../../docs/api.md); резервное копирование —
[backup-restore](../../docs/backup-restore.md).
